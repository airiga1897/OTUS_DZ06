# Проверки и результаты

## Ручная проверка

Все команды выполняются в PowerShell из корня клона после подготовки
инструментов и загрузки реквизитов, описанных в [README](../README.md).

| Команда | Ожидаемое поведение |
| --- | --- |
| `scripts/lab.py deploy` | Стенд развёрнут и оставлен работающим |
| Повторный `scripts/lab.py deploy` | Конфигурация применена; существующие ресурсы, записи и media сохранены |
| `scripts/lab.py verify` | Приложение читает и записывает данные; после выключения лидера выбран новый; выключенный узел восстановлен |
| `scripts/lab.py open` | Выведены размещение и URL, открыт портал |
| `scripts/lab.py destroy` | Ресурсы удалены, отсутствие подтверждено state и API |

Проверка приложения и отказоустойчивости:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py verify
if ($LASTEXITCODE -ne 0) { throw 'Проверка не пройдена; сохраните стенд и диагностику' }
```

`verify` записывает контрольные данные через Django и HAProxy, проверяет HTTP,
выключает текущий ведущий узел через Selectel API и ожидает нового лидера.
После проверки возвращает выключенную ВМ и проверяет записи на всех узлах.
Контрольные статьи создаются неопубликованными, media проверяется на сохранность.

При просмотре портала должны быть доступны шесть учебных материалов.
Статьи `baseline`, `failover`, `recovered` на главной странице отсутствуют.
Ссылки на исходники открывают `develop`, явно заданные ссылки на PR сохраняются.

## Временное испытание — уничтожает тестовый стенд

Для отдельного временного испытания из состояния без действующего стенда:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py test-cycle
```

Команда создаёт стенд, проверяет повторный deploy, данные, фейловер
и восстановление, затем удаляет созданные ресурсы, включая случай ошибки.
При существующем стенде, непустом state или незавершённой операции запуск
отклоняется. При ошибке удаления сохраняются файлы восстановления.
Обычный `deploy` оставляет стенд работающим; удаление выполняется отдельно.
