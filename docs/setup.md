# Подготовка окружения

## Проект Selectel

Создайте аккаунт, облачный проект и сервисного пользователя с доступом
к проекту. Его роль должна позволять управлять ВМ, дисками, сетями,
группами безопасности, публичными IP и группами размещения ВМ, читать
образы, конфигурации ВМ, квоты и консольный вывод.

Номер аккаунта берётся из панели Selectel, ID проекта — из свойств проекта,
имя и пароль — из настроек сервисного пользователя. Эти значения вводятся
при запуске `scripts/env.ps1`. Облачные права определяются ролью пользователя;
дополнительно скрипты ограничивают операции ресурсами и state ДЗ06.

## Инструменты

Команды выполняются в PowerShell из корня клона. Нужны Python 3.12+, Git,
OpenSSH и Terraform 1.6–1.x. Запустите `scripts/setup.ps1`, как показано в README.
Скрипт создаёт собственные `.tools/venv` и `.tools/terraform.exe`.
Серверная ОС — Ubuntu 24.04; Ansible автоматически устанавливается на ВМ
приложения. Соседние проекты не используются при запуске.

## Реквизиты

Основной вариант для ревью — ввод без сохранения в файл:

```powershell
. .\scripts\env.ps1
```

Явные варианты для разработки, выполняемые по отдельности:

```powershell
# Ввести и сохранить локально
. .\scripts\env.ps1 -SaveLocal

# Сохранить уже введённые реквизиты из текущей сессии
. .\scripts\env.ps1 -SaveLocal -UseSession

# Загрузить сохранённые реквизиты; равнозначный ключ — -Dev
. .\scripts\env.ps1 -Development
```

`-SaveLocal` и `-Development` взаимоисключающие. `-UseSession` требует
`-SaveLocal` и полного набора значений в окружении. Пароль вводится скрыто.
Файл `.local/operator.json` доступен только текущему пользователю и исключён
из Git. Перед чтением проверяются его владелец и права. Python и Terraform
получают реквизиты только из окружения; схема полей — `config/selectel-auth.json`.
Реквизиты разных облачных провайдеров не смешиваются.

## Параметры стенда и доступ

Размеры ВМ и политика размещения находятся в `config/placement.json`,
состав узлов — в `config/topology.json`, версии и параметры служб —
в `config/stack.json`. По умолчанию приоритетен ru-9a, резервный пул — ru-3;
ru-7 исключён. В каждой подходящей зоне выбирается первый доступный тип диска:
`basicssd`, затем `universal`. Проверяются образ, квоты и отсутствие конфликта сетей.
При подтверждённой нехватке хостов первое развёртывание переходит к следующему
кандидату только после удаления частичной попытки и проверки state и API.
Выбранное размещение действующего стенда сохраняется.

Внешний публичный IPv4 оператора определяется двумя независимыми HTTPS-сервисами;
ответы должны совпасть. SSH работает на TCP/22 и разрешён только для отдельных
подтверждённых `/32`. Дополнительные адреса задаются явно в `admin_cidrs`.
ВМ БД доступны по приватной сети через ВМ приложения.
При расхождении маршрутов используется подписанная HTTP-проба; перед запуском
Nginx она останавливается. Правила действующего стенда не заменяются автоматически.

При недоступности SSH проверьте фактический выход в интернет, включая VPN,
прокси и туннель роутера, затем текущий IPv4 и разрешённые `/32`.
До выяснения причины не запускайте повторные платные развёртывания для диагностики.

## Локальные файлы и удаление

State находится в `terraform-selectel/terraform.tfstate`, контекст, SSH-ключи,
секреты приложения и журналы — в `.local/`. Они исключены из Git.
Не удаляйте их до подтверждённой очистки облачных ресурсов.

`destroy` проверяет удаление через state и API и затем очищает служебные файлы.
При ошибке сохраняются данные для повторного удаления. Файл реквизитов
разработки удаляется отдельной командой из README после успешного `destroy`.
