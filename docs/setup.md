# Подготовка окружения

Все команды README выполняются локально, из корня клонированного репозитория,
в Windows PowerShell с Python 3.12. Серверы Ubuntu настраиваются автоматически
через SSH; выполнять команды установки вручную на ВМ не требуется.

## Аккаунт и проект Selectel

До запуска необходимо самостоятельно создать аккаунт Selectel, облачный проект
и сервисного пользователя с доступом к этому проекту. Его облачная роль должна
позволять управлять ВМ, дисками, сетями, группами безопасности, публичными IP
и группами размещения ВМ, а также читать квоты, образы, конфигурации ВМ
и консольный вывод. Назначение роли выполняется в панели Selectel.

Номер аккаунта берётся из панели управления, UUID проекта — из свойств проекта,
имя и пароль — из настроек созданного сервисного пользователя. Используются
пул `ru-7` и зона `ru-7a`. Требуемые ресурсы перечислены в README; `prepare`
проверяет свободные квоты с учётом уже работающих стендов.

ID проекта вводится при загрузке окружения. Менять исходный код для другого
аккаунта или оператора не требуется. При работе сохраняется локальная привязка
стенда к ID проекта и региону в `.local/context.json`. Если state содержит
ресурсы, скрипт отклоняет реквизиты другого проекта до обращения к Terraform.
После удаления ресурсов пустой стенд можно подготовить для другого проекта.
Это программная проверка; облачные права оператора определяются его ролью Selectel.

## Инструменты и параметры

Установить Git, Python 3.12 и Terraform версии >= 1.6, < 2. Перед `prepare`
указать расположение собственного Terraform в той же сессии PowerShell:

```powershell
$env:OTUS_TERRAFORM = 'C:\Tools\Terraform\terraform.exe'
```

Путь является примером: требуется существующий бинарник на рабочем компьютере.
Наличие соседнего ДЗ04 не обязательно: исходники приложения включены в ДЗ06.
При отсутствии `OTUS_TERRAFORM` скрипт ищет бинарник в соседнем каталоге ДЗ04.

Основной способ авторизации — команда `env.ps1` из README. Она запрашивает
номер аккаунта, ID проекта, имя оператора и скрытый пароль. Параметры хранятся
только в окружении текущего процесса; файл с ними не создаётся.
После закрытия PowerShell авторизацию необходимо загрузить заново.

Для разработки локальное сохранение включается только явно:

```powershell
. .\scripts\env.ps1 -SaveLocal
```

Скрипт запрашивает те же реквизиты, создаёт `.local/operator.json` с доступом
только текущего пользователя и задаёт `OTUS_SELECTEL_AUTH`. Без этого параметра
обычный запуск `env.ps1` не создаёт и не читает файл. Python-загрузчик проверяет
права доступа к явно выбранному файлу и отклоняет общий доступ.

После завершения разработки файл удаляется. Успешный `destroy` автоматически
удаляет собственный `.local/operator.json`; при ошибке очистки он сохраняется
для повторного запуска. Удаление реквизитов при сохранении работающего стенда:

```powershell
Remove-Item -LiteralPath .local/operator.json
Remove-Item Env:OTUS_SELECTEL_AUTH -ErrorAction SilentlyContinue
```

Для последующих команд заново загрузить окружение через `env.ps1`. Контекст,
state, SSH-ключи и секреты приложения сохраняются локально до удаления стенда;
их удаление не заменяет `destroy`.

Схема реквизитов, имена переменных окружения, адрес API и регион определены
в одном месте — [config/selectel-auth.json](../config/selectel-auth.json).
[credentials.py](../scripts/credentials.py) загружает и проверяет реквизиты;
остальные скрипты используют этот интерфейс. Реальных значений реквизитов
в схеме и документации нет.

## Автоматическая подготовка

`prepare` определяет образ Ubuntu 24.04 и конфигурации ВМ через API, проверяет
квоты и отсутствие пересечения подсети, создаёт SSH-ключ и случайные пароли.
Затем записывает параметры Terraform и выполняет `init` и `validate`.
OpenStack provider 3.4.0 загружается через зеркало из
[terraform-selectel.rc](../terraform-selectel.rc).

Адрес оператора определяется автоматически. Несколько разрешённых IPv4 можно
указать в массиве `admin_cidrs` локального файла
`terraform-selectel/terraform.tfvars.json`, например:

```json
"admin_cidrs": ["192.0.2.10/32", "198.51.100.20/32"]
```

Это фрагмент существующего JSON, а не замена всего файла. Адреса в примере
нужно заменить собственными. Допускаются только отдельные IPv4 с маской `/32`.
Повторный `prepare` сохраняет список и добавляет определённый текущий адрес.
SSH ВМ приложения доступен на TCP/22; доступ к ВМ БД идёт через неё
по приватной сети, также на TCP/22.
Приватные адреса, шлюз и DNS задаются на ВМ через Netplan из параметров
Terraform. После записи конфигурации cloud-init выполняет `netplan apply`.

## Локальные файлы

| Путь | Содержимое |
| --- | --- |
| `.local/context.json` | Привязка стенда к проекту и региону без пароля и имени оператора |
| `.local/otus_dz06` и `.pub` | Приватный и публичный SSH-ключи |
| `.local/secrets.json` | Случайные пароли БД и ключи приложения |
| `.local/known_hosts`, `.local/trusted-hosts.json` | Проверенные через облачный API SSH-ключи серверов |
| `.local/cleanup-fips.json` | UUID собственных floating IP для повторного аудита после очистки state |
| `.local/runs/` | Полные журналы команд |
| `terraform-selectel/terraform.tfvars.json` | Параметры конкретного запуска |
| `terraform-selectel/terraform.tfstate` | Состояние созданной инфраструктуры |

Эти данные исключены из Git через [.gitignore](../.gitignore). Состояние Terraform
нужно сохранять до подтверждённого удаления стенда. Команда `destroy` удаляет
облачные ресурсы, но оставляет локальные ключи, параметры и журналы.

Реквизиты оператора фильтруются при записи журналов и публикуемых отчётов.
Технические ID облачных ресурсов сохраняются локально в state и контексте,
а доказательства проверок содержат обезличенные результаты. Файл разработчика
не передаётся на ВМ. После окончания сессии PowerShell следует закрыть окно,
чтобы удалить реквизиты из его окружения.
